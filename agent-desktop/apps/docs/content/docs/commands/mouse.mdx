title: Mouse commands
navTitle: Mouse
description: Reference for hover, drag, mouse-move, mouse-click (including Windows background clicks), mouse-down, mouse-up, and mouse-wheel. Cursor movement needs --headed, and the held-button commands fail closed.
---

Mouse commands move the real cursor, so they need the global `--headed` flag. The one exception is [`mouse-click --background`](#mouse-click) on Windows, which posts the click to a window as messages. Without `--headed`, a cursor-moving command returns `POLICY_DENIED` with `not_delivered` and sends nothing:

```json
{
  "code": "POLICY_DENIED",
  "message": "hover moves the cursor and is disabled in headless mode",
  "recovery": { "strategy": "request_explicit_policy_then_retry_original", "retryable": true, "requires_fresh_snapshot": false },
  "disposition": { "delivery": "not_delivered", "retry": "safe" }
}
```

Read [Headed mode](/desktop/guides/headed-mode) before you add the flag. Coordinates are absolute screen points written `x,y`; write a negative value with `=` so the shell does not read it as a flag (`--xy=-100,50`). Raw coordinates carry no window identity and never focus an app; a ref target focuses its exact window first. The pointer commands return an [OperationReport](/desktop/json-output#operationreport) with a `pointer` target. The examples below are trimmed.

## hover

Moves the cursor to an element's center or to a point.

```bash
agent-desktop --headed hover @s8f3k2p9:e5
agent-desktop --headed hover --xy 640,400
```

<table>
  <thead>
    <tr><th>Flag or argument</th><th>Default</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>REF</code></td><td>none</td><td>Qualified ref. Wins over <code>--xy</code>.</td></tr>
    <tr><td><code>--xy X,Y</code></td><td>none</td><td>Absolute coordinates. One of <code>REF</code> or <code>--xy</code> is required.</td></tr>
    <tr><td><code>--duration MS</code></td><td>none</td><td>Reserved. A positive value is rejected; run <code>hover</code>, then <code>wait MS</code>.</td></tr>
    <tr><td><code>--timeout-ms MS</code></td><td><code>5000</code></td><td>Budget for the ref to resolve and become actionable.</td></tr>
  </tbody>
</table>

```json
{
  "version": "2.6",
  "ok": true,
  "command": "hover",
  "data": {
    "action": "mouse-move",
    "details": { "delivered_events": 1 },
    "disposition": { "delivery": "delivered_unverified", "retry": "unsafe" },
    "steps": [{ "label": "pointer_move", "mechanism": "physical_synthetic", "outcome": "succeeded" }],
    "target": { "kind": "pointer", "point": { "x": 640.0, "y": 400.0 } },
    "x": 640.0,
    "y": 400.0
  }
}
```

For a ref, the cursor goes to the center of the live bounds after visibility, stability, and hit-test checks. Errors: `INVALID_ARGS` for a missing target or bad coordinates; `ACTION_FAILED` when another element covers the target; the ref errors `STALE_REF`, `AMBIGUOUS_TARGET`, and `SNAPSHOT_NOT_FOUND`.

## drag

Presses at one point, moves to another, and releases.

```bash
agent-desktop --headed drag --from @s8f3k2p9:e1 --to @s8f3k2p9:e5
agent-desktop --headed drag --from-xy 100,200 --to-xy 400,500 --drop-delay 800
```

<table>
  <thead>
    <tr><th>Flag</th><th>Default</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--from REF</code>, <code>--from-xy X,Y</code></td><td>required, one of</td><td>Source element or point.</td></tr>
    <tr><td><code>--to REF</code>, <code>--to-xy X,Y</code></td><td>required, one of</td><td>Destination element or point. The two kinds can be mixed.</td></tr>
    <tr><td><code>--duration MS</code></td><td>platform default</td><td>Length of the movement, at most 60000.</td></tr>
    <tr><td><code>--drop-delay MS</code></td><td><code>500</code></td><td>Hold over the destination before releasing, so the drop target activates. At most 10000.</td></tr>
    <tr><td><code>--timeout-ms MS</code></td><td><code>5000</code></td><td>Budget for the whole gesture. <code>--duration</code> plus <code>--drop-delay</code> must be below it.</td></tr>
    <tr><td><code>--wait-for-scope to|from</code></td><td><code>to</code></td><td>Which endpoint's window a post-action <code>--wait-for</code> polls.</td></tr>
  </tbody>
</table>

The destination app is never focused first, because raising it could cover the source. The report describes the gesture (`target.kind: "drag"` with `from` and `to`), not its outcome, so verify the moved item with a fresh snapshot. Native cross-app drag and drop can ignore synthetic events. Errors: `INVALID_ARGS` for a missing endpoint or timing that does not fit `--timeout-ms`, `TIMEOUT` when preparation used up the budget, and the errors listed under [`hover`](#hover).

## mouse-move

Moves the cursor to absolute coordinates.

```bash
agent-desktop --headed mouse-move --xy 700,450
```

The report matches the [`hover`](#hover) example.

## mouse-click

Clicks at absolute coordinates. On Windows, `--background` posts the click to one window as window messages. It needs no `--headed`, and the cursor and focus stay where they are unless you add `--cursor-fallback` or `--restore-minimized`.

```bash
agent-desktop --headed mouse-click --xy 500,300 [--button left|right|middle] [--count N] [--modifiers NAME]...
agent-desktop mouse-click --background --window-id ID --xy X,Y [--button left|right|middle] [--count N] [--restore-minimized] [--cursor-fallback] [--semantic]
agent-desktop mouse-click --background --window-id ID --capture-id CAPTURE_ID --xy PX,PY [--button left|right|middle] [--count N] [--restore-minimized] [--cursor-fallback] [--semantic]
```

<table>
  <thead>
    <tr><th>Flag</th><th>Default</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--xy X,Y</code></td><td>required</td><td>Absolute screen coordinates, or image pixels when <code>--capture-id</code> is present.</td></tr>
    <tr><td><code>--button</code></td><td><code>left</code></td><td><code>left</code>, <code>right</code>, or <code>middle</code>.</td></tr>
    <tr><td><code>--count N</code></td><td><code>1</code></td><td>Clicks, 1 to 100. Use 2 for a double click and 3 for a triple click. With <code>--background</code>, each click is posted on its own, 100 ms apart, and no double-click message is sent.</td></tr>
    <tr><td><code>--modifiers NAME</code></td><td>none</td><td>A modifier held during the click: <code>shift</code>, <code>meta</code>, <code>ctrl</code>, <code>alt</code>. Repeat the flag for several. Rejected with <code>--background</code>.</td></tr>
    <tr><td><code>--background</code></td><td>off</td><td>Post the click to <code>--window-id</code> as window messages. Windows only. Needs no <code>--headed</code>. The cursor and focus stay put unless <code>--cursor-fallback</code> or <code>--restore-minimized</code> is added.</td></tr>
    <tr><td><code>--window-id ID</code></td><td>none</td><td>Target window for <code>--background</code>; required with it and from <code>list-windows</code>.</td></tr>
    <tr><td><code>--capture-id ID</code></td><td>none</td><td>A <code>capture_id</code> from <code>screenshot --window-id</code>; makes <code>--xy</code> image pixels. Requires <code>--background</code>.</td></tr>
    <tr><td><code>--restore-minimized</code></td><td>off</td><td>With <code>--background</code>, restore a minimized target for the click, then minimize it again. The window is shown, and can take focus, while it is restored.</td></tr>
    <tr><td><code>--cursor-fallback</code></td><td>off</td><td>With <code>--background</code>, aim the cursor at the point while messages are posted, then restore it, for frameworks that read the physical cursor.</td></tr>
    <tr><td><code>--semantic</code></td><td>off</td><td>With <code>--background</code>, invoke the UI Automation element at the point instead of posting mouse messages. Works while the window is covered and for frameworks that ignore posted input. Left button only. Falls back to posted messages when nothing at the point can be invoked.</td></tr>
  </tbody>
</table>

```json
{
  "version": "2.6",
  "ok": true,
  "command": "mouse-click",
  "data": {
    "action": "mouse-click",
    "count": 1,
    "details": { "delivered_events": 3 },
    "disposition": { "delivery": "delivered_unverified", "retry": "unsafe" },
    "steps": [{ "label": "pointer_click", "mechanism": "physical_synthetic", "outcome": "succeeded" }],
    "target": { "kind": "pointer", "point": { "x": 1300.0, "y": 880.0 } },
    "x": 1300.0,
    "y": 880.0
  }
}
```

`target.point` is where the click was dispatched; it does not prove which app received it. Before you click at bounds read from a snapshot, check `get --property bounds` and its `live` flag.

With `--background`, the click goes to the window, or to the child control under the point, as `WM_MOUSEMOVE`, a button-down message, and a button-up message. `--count N` repeats that sequence 100 ms apart. No double-click message is posted, so a control that acts only on that message may not react. The disposition is `delivered_unverified`: the messages were accepted, not proven to have changed the app, so verify from fresh state.

`data` echoes the request as `window_id`, `space` (`screen`, or `image` with `--capture-id`), `screen_x`, `screen_y`, `restore_minimized`, `cursor_fallback`, and `semantic`. With `--capture-id` it also carries `capture_id`, `image_x`, and `image_y`. `data.details` describes the delivery:

<table>
  <thead>
    <tr><th>Field</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>method</code></td><td><code>PostMessage</code>, <code>PostMessage+cursor</code> with <code>--cursor-fallback</code>, or <code>UIA.Invoke</code> when <code>--semantic</code> invoked an element.</td></tr>
    <tr><td><code>background</code></td><td>Always <code>true</code>.</td></tr>
    <tr><td><code>target_hwnd</code></td><td>The window that received the messages, as a window id: the child control under the point when there is one, otherwise the target window.</td></tr>
    <tr><td><code>client_x</code>, <code>client_y</code></td><td>The point in the client coordinates of <code>target_hwnd</code>.</td></tr>
    <tr><td><code>window_was_minimized</code>, <code>restored_for_click</code></td><td>Whether the target was minimized, and whether it was restored for the click.</td></tr>
    <tr><td><code>cursor_fallback</code>, <code>semantic_requested</code></td><td>Whether those flags were passed.</td></tr>
  </tbody>
</table>

`--semantic` finds the UI Automation element under the point inside the target window's own subtree, so it also works while another window covers the target. It invokes that element, or the nearest ancestor that can be invoked, once per `--count`, and accepts only the left button. The report then carries `method: "UIA.Invoke"`, `count`, and `semantic: true` in place of the window and client fields, and the cursor does not move even with `--cursor-fallback`. When nothing at the point can be invoked, the click falls back to posted messages: `details.method` is a `PostMessage` value and `details.semantic_requested` is `true`.

A background click is refused before anything is sent in these cases:

- `STALE_REF` with `details.kind: "stale_capture"` and a `details.reason`: the capture belongs to another window, the window moved or resized since the capture, its process instance changed, or the capture is older than the capture-age limit. The limit is 10 seconds; set `AGENT_DESKTOP_MAX_CAPTURE_AGE_MS` to a larger millisecond value when a vision round-trip is slower.
- `INVALID_ARGS`: the window is minimized and `--restore-minimized` is absent, the point is outside the client area or outside the captured image, the `capture_id` cannot be decoded, `--semantic` is combined with a right or middle button, or `--modifiers` is present.
- `WINDOW_NOT_FOUND`: no window has that id.
- `PERM_DENIED` with `details.win32_error`: the target refused the message, as a window at a higher integrity level does.

Some frameworks ignore posted messages. A classic Win32 button was verified to click while its window was unfocused and the cursor was elsewhere. A WinForms control checks the physical cursor position and async key state, so a posted click and `--cursor-fallback` do nothing; `--semantic` invokes it. Use a ref action when the control has one, and verify every background click.

## mouse-down

Reserved name for pressing and holding a button. It never sends input.

```bash
agent-desktop --headed mouse-down --xy 500,300 [--button NAME] [--modifiers NAME]...
```

The first failing check decides the error: a bad argument is `INVALID_ARGS`; headless is `POLICY_DENIED` (`not_delivered`); with `--headed`, the command ends in `ACTION_NOT_SUPPORTED`, `mouse-down is unavailable in stateless mode`, with a disposition of `unknown` and no event sent. Use [`mouse-click`](#mouse-click) or [`drag`](#drag).

## mouse-up

Reserved name for releasing a held button. It fails closed through the same checks as [`mouse-down`](#mouse-down).

```bash
agent-desktop --headed mouse-up --xy 500,300
```

## mouse-wheel

Scrolls the mouse wheel at absolute coordinates. Use it for canvases and custom surfaces with no accessibility scroll action; for a scroll area with a ref, use [`scroll`](/desktop/commands/scroll#scroll).

```bash
agent-desktop --headed mouse-wheel --x 700 --y 400 --dy -2
```

<table>
  <thead>
    <tr><th>Flag</th><th>Default</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--x X</code>, <code>--y Y</code></td><td>required</td><td>Absolute coordinates.</td></tr>
    <tr><td><code>--dy LINES</code></td><td><code>-3</code> when <code>--dx</code> is 0, else 0</td><td>Vertical lines. Positive scrolls up, negative scrolls down.</td></tr>
    <tr><td><code>--dx LINES</code></td><td><code>0</code></td><td>Horizontal lines. Positive scrolls right.</td></tr>
    <tr><td><code>--modifiers NAME</code></td><td>none</td><td>Modifiers held during the scroll; repeatable.</td></tr>
  </tbody>
</table>

```json
{
  "version": "2.6",
  "ok": true,
  "command": "mouse-wheel",
  "data": {
    "action": "mouse-wheel",
    "details": { "delivered_events": 5 },
    "disposition": { "delivery": "delivered_unverified", "retry": "unsafe" },
    "dx": 0.0,
    "dy": -2.0,
    "steps": [{ "label": "pointer_wheel", "mechanism": "physical_synthetic", "outcome": "succeeded" }],
    "target": { "kind": "pointer", "point": { "x": 700.0, "y": 400.0 } }
  }
}
```

Mouse commands need `--headed`; `mouse-click --background` is the exception. See [Windows](/desktop/platforms/windows#what-works-headless).
