title: Docker containers
navTitle: Docker containers
description: Why agent-desktop cannot run in a Docker container, and what to use instead when you need an isolated Windows desktop.
---

agent-desktop needs the interactive desktop session of a signed-in Windows user. That session is where UI Automation reads windows and where input is delivered. A Docker container does not provide one: Docker Desktop's containers do not run a Windows desktop, and Windows containers have no interactive desktop session. The released binary therefore cannot observe or drive apps inside a container.

## What to use instead

- **A Windows virtual machine.** Install Windows, sign in, and run agent-desktop in that session. The requirements are on the [Windows page](/desktop/platforms/windows#requirements).
- **The host desktop.** Run agent-desktop in your own signed-in session. State lives under the [state root](/desktop/configuration#state-root); `AGENT_DESKTOP_HOME` relocates it when you want a scratch directory.

The `sandbox` commands do not manage Docker containers, and this build ships no sandbox providers. See [Sandboxes](/desktop/sandboxes).
