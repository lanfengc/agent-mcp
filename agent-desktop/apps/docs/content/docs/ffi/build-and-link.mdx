Use a prebuilt archive from a release, or build the library from source with the `release-ffi` profile.

## Prebuilt archives

Every GitHub release ships `agent-desktop-ffi-v<version>-<target>.zip` for Windows x64 and ARM64. The archive holds a top-level `agent-desktop-ffi-v<version>-<target>/` directory:

<table>
  <thead>
    <tr><th>Path</th><th>Contents</th></tr>
  </thead>
  <tbody>
    <tr><td><code>lib/</code></td><td><code>agent_desktop_ffi.dll</code>, plus <code>agent_desktop_ffi.dll.lib</code>, the import library for MSVC</td></tr>
    <tr><td><code>include/agent_desktop.h</code></td><td>The generated C header</td></tr>
  </tbody>
</table>

`checksums.txt` in the release catches corruption; verify origin with `gh attestation verify <file> --repo vercel-labs/agent-desktop`.

## Build from source

```powershell
cargo build --profile release-ffi -p agent-desktop-ffi    # writes target\release-ffi\agent_desktop_ffi.dll
```

The output is `agent_desktop_ffi.dll` in `target\release-ffi\` for the host target, or `target\<target>\release-ffi\` when you pass `--target`. The crate also emits `agent_desktop_ffi.dll.lib`, the import library for MSVC. The `release-ffi` profile keeps `panic = "unwind"`, so every entrypoint can catch a panic and report it as `AD_RESULT_ERR_INTERNAL`. The workspace `release` profile uses `panic = "abort"`, so `cargo build --release` produces a library whose panics abort the host process. Do not ship it.

## The header

`crates/ffi/include/agent_desktop.h` is generated by cbindgen; do not edit it. When the Rust ABI or `crates/ffi/cbindgen.toml` changes, regenerate it with `scripts/update-ffi-header.sh`, and CI fails on drift. The header ends with C11 `_Static_assert` guards that pin the size and field offsets of every size-pinned struct; define `AGENT_DESKTOP_ABI_ASSERTS` to skip them.

## Link and run a program

This program checks the ABI, snapshots one app, and prints the envelope:

```c
#include <stdio.h>
#include "agent_desktop.h"

int main(int argc, char **argv) {
    const char *app = argc > 1 ? argv[1] : NULL;   /* NULL reads the focused window */

    if (ad_init(AD_ABI_VERSION_MAJOR) != AD_RESULT_OK) {
        fprintf(stderr, "ABI mismatch: %s\n", ad_last_error_message());
        return 1;
    }

    AdAdapter *adapter = ad_adapter_create();
    if (!adapter) {
        fprintf(stderr, "adapter_create failed: %s\n", ad_last_error_message());
        return 1;
    }

    char *json = NULL;
    AdResult rc = ad_snapshot(adapter, app, AD_SNAPSHOT_SURFACE_WINDOW,
                              3, true, true, &json);   /* max_depth, interactive_only, compact */
    if (json) {                      /* an ok:true or ok:false envelope: free either */
        printf("%s\n", json);
        ad_free_string(json);
    } else {
        fprintf(stderr, "snapshot failed (%d): %s\n", (int)rc, ad_last_error_message());
    }

    ad_adapter_destroy(adapter);
    return rc == AD_RESULT_OK ? 0 : 1;
}
```

Compile and run it from the repository root in a Developer Command Prompt for Visual Studio:

```powershell
cl /std:c11 /I crates\ffi\include main.c /link /LIBPATH:target\release-ffi agent_desktop_ffi.dll.lib /OUT:snapshot_demo.exe
.\snapshot_demo.exe notepad.exe
```

The DLL must be beside the executable or in a directory on `PATH` when the program runs; copy `target\release-ffi\agent_desktop_ffi.dll` beside `snapshot_demo.exe`.

The library returns the same envelope as the CLI. Against Notepad it has this shape, with the window metadata and `tree` elided:

```json
{"version":"2.6","ok":true,"command":"snapshot","data":{"app":"notepad.exe","complete":true,"ref_count":17,"snapshot_id":"s2jmdx3amedsce","window":{"id":"w-299895934","title":"Untitled - Notepad"},"tree":{"...":"..."}}}
```

An MSVC program links `agent_desktop_ffi.dll.lib` and loads `agent_desktop_ffi.dll` at run time through the standard Windows DLL search order. The program must run in the user's interactive session to see apps; see [Windows](/desktop/platforms/windows#requirements).

## Validate struct sizes

A language whose struct layout can differ from C's, such as Python `ctypes` or Go `cgo`, must check each size-pinned struct before passing one to the library. Each has an `AD_*_SIZE` macro and a runtime getter that returns the size compiled on the Rust side: `AdAction` (`ad_action_size`), `AdActionResult`, `AdActionStep`, `AdDisplayInfo`, `AdDragParams`, `AdElementState`, `AdExactRefEntry`, `AdExactSurfaceInfo`, `AdExactWindowInfo`, `AdRefEntry`, and `AdWaitArgs`, each with a matching `ad_<name>_size()` getter.

Zero-initialize every caller-allocated struct before you set fields, and set the `version` and `size` fields of versioned structs to the header's constants.

## Smoke test

`tests/ffi-python/smoke.py` is the reference for non-C hosts and uses only the Python standard library. It checks the ABI version, the size getters, `ad_version`, and the create, snapshot, free, and destroy cycle:

```powershell
python tests\ffi-python\smoke.py target\release-ffi\agent_desktop_ffi.dll crates\ffi\include\agent_desktop.h
```

A passing run ends with `All legs passed.`
