A surface is a UI layer that you observe separately from a window or application's full accessibility tree: an open menu, a sheet, or an OS shell area such as the taskbar. While an overlay is open, the refs from the window behind it are the wrong target, so read the overlay itself.

```bash
agent-desktop snapshot --app notepad.exe --surface menu -i --compact
agent-desktop find --app notepad.exe --surface menu --name "Save" --exact --first
```

Open Notepad's File menu first. The next sections show the results.

## Surface kinds

`--surface` takes these values on `snapshot` and `find`. The default is `window`. Names with hyphens also accept underscores, such as `system_tray`.

<table>
  <thead>
    <tr><th>Group</th><th>Kinds</th></tr>
  </thead>
  <tbody>
    <tr><td>The app or window and its layers</td><td><code>window</code>, <code>focused</code>, <code>menu</code>, <code>sheet</code></td></tr>
    <tr><td>OS shell</td><td><code>start-menu</code>, <code>taskbar</code>, <code>system-tray</code>, <code>system-tray-overflow</code>, <code>action-center</code></td></tr>
  </tbody>
</table>

There is no `menubar` surface. `quick-settings` returns `INVALID_ARGS` and names `action-center`. Per-kind limits are on [Windows](/desktop/platforms/windows#surfaces).

## Check what is supported

`status` reports `supported_surfaces` for the current machine and session:

```json
{ "supported_surfaces": ["window", "focused", "sheet", "menu", "start-menu", "taskbar", "system-tray", "system-tray-overflow", "action-center"] }
```

Read it before you ask for a surface. A kind this build does not expose fails with `INVALID_ARGS`, with the supported list in `details.supported_surfaces` and your request in `details.requested_surface`. An empty `supported_surfaces` means UIA did not answer, not that the desktop is empty.

## Know when a surface opened

You rarely need to poll for a surface. `click`, `double-click`, `right-click`, `triple-click`, `expand`, `select`, and `press` report the surfaces open after the action in `data.surfaces`. This is the result of clicking Notepad's File menu:

```json
{
  "surfaces": [
    { "id": "w-10424664", "title": "Untitled - Notepad", "type": "window" },
    { "id": "w-10424664", "title": "Untitled - Notepad", "type": "focused" },
    { "id": "w-13435630", "item_count": 8, "title": "File", "type": "menu" }
  ]
}
```

A `menu` or `sheet` entry means the app is waiting on that overlay. Observe it next with `snapshot --surface` or `find --surface`. The field is omitted when nothing is open or the read failed.

## Snapshot or search a surface

```bash
agent-desktop snapshot --app notepad.exe --surface menu -i --compact
```

To reach one item, `find --surface` is cheaper than a dump:

```json
{
  "version": "2.6",
  "ok": true,
  "command": "find",
  "data": {
    "match": {
      "interactive": true,
      "name": "Save",
      "path": ["menu:File"],
      "ref_id": "@s2f1l46zd8bpfj:e1",
      "role": "menuitem",
      "states": [],
      "value": null
    },
    "snapshot_id": "s2f1l46zd8bpfj"
  }
}
```

How agent-desktop selects an owner depends on the kind:

- `sheet`: the app's accessible windows in order, focused first and then visible, and the first that presents one wins. With no `--app`, the frontmost process.
- `menu` and `focused` are window-owned, so any app window identifies the process, and several open windows are not ambiguous.
- A shell kind needs no `--app`, because no application owns it.
- For window-owned surfaces, `--window-id` pins the read to that window.

A missing `complete`, `complete: false`, a timeout, or an incomplete accessibility read leaves menu absence unknown. After a delivery with `retry: unsafe`, inspect the current UI before taking another action.
A surface that is not open returns an error. On Windows, a closed `menu` returns `WINDOW_NOT_FOUND`:

```json
{
  "code": "WINDOW_NOT_FOUND",
  "message": "No menu this surface can root was found for this application",
  "suggestion": "A classic Win32 menu can be open without exposing an element to root at, so a menu wait can succeed where this refuses. Read the owning window's own surface instead.",
  "disposition": { "delivery": "not_delivered", "retry": "safe" }
}
```

A closed shell surface returns `WINDOW_NOT_FOUND`. `--surface` cannot combine with `--root`, because a ref already carries the surface it was captured from. Do not use `--skeleton` on a surface: it is already small and focused. See [Skeleton and drill-down](/desktop/skeleton-and-drill-down#when-to-skip-the-skeleton).

## List what is open

```bash
agent-desktop list-surfaces --app notepad.exe
```

```json
{
  "version": "2.6",
  "ok": true,
  "command": "list-surfaces",
  "data": {
    "pid": 19092,
    "surfaces": [
      { "id": "w-68555078", "title": "Untitled - Notepad", "type": "window" },
      { "id": "w-68555078", "title": "Untitled - Notepad", "type": "focused" },
      { "id": "w-31459802", "item_count": 8, "title": "File", "type": "menu" }
    ]
  }
}
```

`list-surfaces` returns the overlays an app presents now, which are the kinds `snapshot --surface` accepts for it. Shell surfaces belong to the OS and never appear here. An entry can carry `"unclassified": ["sheet"]` or `["menu"]` when the check could not read that window, often because the app was busy. Treat the missing entry as unknown, not absent.

## Open an OS shell surface

`open-system-surface` raises a shell surface. It returns the window the surface presents, in the `w-<id>` form that `list-windows` uses:

```bash
agent-desktop --headed open-system-surface --surface action-center
agent-desktop snapshot --surface action-center -i --compact
```

It takes the foreground, so headless mode refuses it with `POLICY_DENIED`; pass `--headed` (see [Headed mode](/desktop/guides/headed-mode)). An already-present surface returns without being raised again. A kind this build does not expose returns `INVALID_ARGS` with the kinds to use instead. Which kinds open is on the [Windows page](/desktop/platforms/windows#surfaces).
