agent-desktop has no configuration file. Behavior comes from global flags on each command, a few environment variables, and the state root directory where snapshots, sessions, and traces live.

## Global flags

Global flags work before or after the command name, so `agent-desktop --headed click REF` and `agent-desktop click REF --headed` are the same. `agent-desktop --help` lists them.

## Post-action wait flags

`--wait-for`, `--wait-for-gone`, and `--wait-timeout` make a command wait for the UI to show its effect. The command runs first; then the flag polls the accessibility tree until the selector is satisfied or the timeout ends. [Waiting without sleeps](/desktop/guides/waiting) compares them with the [`wait`](/desktop/commands/wait) command.

**Selector.** `role:text`, split at the first `:`. `button` matches by role, `:Saved` by text, and `button:Save` by both. Text is a case-insensitive substring of an element's name, value, or description. An empty selector returns `INVALID_ARGS` before the command runs.

**Commands that accept them.** `snapshot`, `press`, `hover`, `drag`, and every ref action (`click`, `double-click`, `triple-click`, `right-click`, `type`, `set-value`, `clear`, `focus`, `select`, `toggle`, `check`, `uncheck`, `expand`, `collapse`, `scroll`, `scroll-to`). Every other command returns `INVALID_ARGS`. `snapshot --root` cannot combine with them, and a `batch` entry never inherits them.

**Which owner is polled.** For `snapshot`, the selected surface owner. For a ref action, the original process. Application-owned refs keep their source surface. Window-owned refs observe their original window, even when captured from `sheet`, `alert`, `popover`, `focused`, or `menu`. The wait reads the whole window, so a selector elsewhere in the window can satisfy `--wait-for` early or keep `--wait-for-gone` from succeeding. To observe the overlay itself, run a separate `snapshot` with the desired `--surface` and wait selector. For `press`, the `--app` or `--window-id` window, else the focused one. For `drag`, the destination window, or the source with `--wait-for-scope from`.

**Results.**

- `--wait-for` succeeds with snapshot data (`snapshot_id`, `ref_count`, `tree`, and so on) plus `elapsed_ms` and `matched_selector`. For an action, the action's own report moves under `data.after_action`.
- `--wait-for-gone` succeeds with `matched_selector`, `gone: true`, `target_absent: true`, and `elapsed_ms`, with the action's report under `after_action`.
- On expiry the command fails with `TIMEOUT`, `details.kind: "wait_timeout"`, `details.selector`, and `details.timeout_ms`. After an action, `details.after_action` holds its report, and the error keeps the action's own delivery disposition, so a timeout does not make the action safe to repeat.
- If a ref action returns `delivery_uncertain`, `error.details.post_action_observation` records read-only evidence from the original process and its application-owned source surface or pinned window. Its [fields and outcomes](/desktop/json-output#post-action-observation) do not change the original error or unsafe retry disposition. The wait uses `--wait-timeout` separately from the action timeout.
- A temporary `ACTION_NOT_SUPPORTED` error with `details.kind: "window_without_accessibility_element"` is retried during wait polling. For `--wait-for-gone`, that error does not count as absence; the wait succeeds only after a complete selector read finds no match or the app/window lookup confirms the target is gone.

```bash
agent-desktop click @s8f3k2p9:e5 --wait-for ":Saved" --wait-timeout 5000
agent-desktop click @s8f3k2p9:e5 --wait-for-gone "progressindicator"
agent-desktop snapshot --app notepad.exe -w "textfield:Text editor"
```

An invalid value returns `INVALID_ARGS` with `not_delivered`, and nothing runs. In PowerShell, set a variable with `$env:AGENT_DESKTOP_HOME = "$env:TEMP\ad-scratch"`.

## Execution policy

The policy is read from the environment of each process, so it also applies to `batch` entries and MCP calls. A restrictive policy refuses `batch` entirely, because a batch could otherwise reach a denied command. Commands run individually with the same policy.

```powershell
# Read-only evaluation: observations, screenshots and reads succeed; clicks and typing do not.
$env:AGENT_DESKTOP_READ_ONLY = '1'
agent-desktop screenshot --window-id w-123 shot.png
Remove-Item Env:AGENT_DESKTOP_READ_ONLY          # end the read-only phase

# Interactive phase: allow only the commands this run needs.
$env:AGENT_DESKTOP_ALLOWED_COMMANDS = 'screenshot,mouse-click,list-windows'
agent-desktop mouse-click --background --window-id w-123 --xy 100,80

# Keep an outcome trail. The log records time, command, ok, error code and duration.
$env:AGENT_DESKTOP_AUDIT_LOG = "$HOME\agent-desktop-audit.jsonl"
agent-desktop list-windows
```

Read-only mode refuses every command that changes an application, the desktop, the clipboard, a session, or a sandbox. That includes `batch`, `cursor-overlay`, and every `session` action except `session list`. `snapshot`, `find`, `get`, `is`, `wait`, the `list-*` commands, `status`, and `permissions` without `--request` still run. So do the three that only write a file you name: `screenshot PATH`, `clipboard-get --out`, and `trace export`. One side effect remains on Windows: a screenshot of a minimized window restores it for the capture and minimizes it again.

Each audit record is one JSON object on its own line with `ts_ms`, `command`, `ok`, `error` (the error code, or `null`), and `duration_ms`. It omits command output, arguments, typed text, and coordinates, so it can be kept without storing application data. The file is opened for appending, and a path that cannot be opened returns `INVALID_ARGS` before anything runs. `sandbox exec` is not recorded.

`AGENT_DESKTOP_READ_ONLY` and `AGENT_DESKTOP_ALLOWED_COMMANDS` are checked before the command touches an application. A refusal is `POLICY_DENIED` with `not_delivered`, and it is recorded in the audit log. On Windows, the check also runs before a command started outside the desktop session is [rerun there](/desktop/platforms/windows#requirements); the caller records that run with `relaunched: true` and the rerun command's `exit_code` in place of `error`.

## State root

agent-desktop keeps its state under one directory: `.agent-desktop` in your user profile by default, `C:\Users\you\.agent-desktop` on a typical install. `agent-desktop status` reports the resolved path as `state_root`. `AGENT_DESKTOP_HOME` replaces the default:

- It must be an absolute path. If it exists, it must be a directory you own and not a junction or symbolic link.
- It does not need to exist yet; it is created on first use with a private DACL that grants only your account, SYSTEM, and Administrators.

On Windows the state root must stay private. A root whose DACL grants access to any other principal makes commands that write there fail with `INTERNAL`, "private file DACL grants an untrusted principal". Remove the extra access entry, or let agent-desktop create the directory. A fresh root per run isolates refs:

```powershell
$env:AGENT_DESKTOP_HOME = Join-Path $env:TEMP "ad-scratch-$([guid]::NewGuid())"   # absolute; created on first use
agent-desktop status                                                                # data.state_root shows this path
```

### Layout

```text
C:\Users\you\.agent-desktop\          state root
  latest_snapshot_id                  newest snapshot in the global namespace
  snapshots/
    s8f3k2p9/refmap.json              one refmap per snapshot
  tmp/                                clipboard-get images outside a session
  sessions/
    run-1793352720537-17009-0/        one directory per session
      session.json                    manifest
      latest_snapshot_id
      snapshots/s8f3k2p9/refmap.json  the session's own namespace
      trace/                          JSONL segments, one per process
      clipboard/                      clipboard-get images inside the session
```

- **Snapshots.** Each snapshot writes `snapshots/<id>/refmap.json`. Size and retention limits are in [Where refs are stored](/desktop/snapshots-and-refs#where-refs-are-stored).
- **Sessions.** `session start` creates `sessions/<id>/` with its own `snapshots/`, so one session's refs are invisible to another. `session gc` deletes ended sessions with their traces. See [Sessions](/desktop/sessions).
- **Traces.** A tracing session writes one JSONL segment per process under `trace/`, plus `screens/` and `refmaps/` with `--screenshots`. See [Traces](/desktop/guides/traces).

The cross-process interaction lock lives outside the state root, at `%ProgramData%\agent-desktop\<your SID>\interaction.lock`, so every agent of one user shares it whatever their `AGENT_DESKTOP_HOME`. Files you name yourself, such as a `--trace` path or a screenshot path, are also outside it.
