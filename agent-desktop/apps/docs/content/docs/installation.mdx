Install the `agent-desktop` npm package globally with npm, pnpm, Yarn, or Bun. It needs Node 18 or later and runs on Windows x64 and ARM64.

```bash
npm install -g agent-desktop     # or: pnpm add -g, yarn global add, bun add -g
agent-desktop version            # confirm the command resolves
```

Without `-g`, the command lands in `./node_modules/.bin` instead of on your PATH. Run it with `npx agent-desktop`, or install globally.

## What the package contains

The package carries a native Windows CLI for both released architectures. No helper binary is installed beside it.

The [C library](/desktop/ffi) is not in the npm package. It ships as a separate archive on each release.

## Release archives

For a native executable without a JavaScript launcher, download the archive for your architecture from [GitHub Releases](https://github.com/vercel-labs/agent-desktop/releases). Extract `agent-desktop.exe` into a directory on your PATH. To upgrade, replace it with the file from the same release.

Checksums catch corruption. Verify origin with the build attestation:

```bash
gh attestation verify <downloaded-archive> --repo vercel-labs/agent-desktop
```

## Blocked install scripts

The package's `postinstall` script replaces the Node launcher with a link to the native binary. If your package manager blocks install scripts, the Node launcher runs instead. It works, but every call starts Node first, which adds more than 100 ms. The launcher prints a one-time notice to stderr with the fix. Allow the script and reinstall:

```bash
npm install -g agent-desktop --allow-scripts=agent-desktop
```

## Package managers

There is no Scoop package, and the repository does not maintain a Scoop bucket. An older install from a third-party manifest stays pinned to its version and can shadow the npm command. Check which executable runs, and uninstall the old one with the package manager that installed it:

```powershell
Get-Command agent-desktop
```

## Build from source

You need the Rust toolchain pinned in `rust-toolchain.toml` (1.89.0), which `rustup` installs on first use, and the MSVC build tools.

```bash
git clone https://github.com/vercel-labs/agent-desktop && cd agent-desktop
cargo build --release -p agent-desktop      # writes target/release/agent-desktop.exe
```

## Verify the install

```bash
agent-desktop version
agent-desktop status
```

`version` prints the CLI version, the architecture, and the OS:

```json
{
  "version": "2.6",
  "ok": true,
  "command": "version",
  "data": { "os": "windows", "target": "x86_64", "version": "1.2.0" }
}
```

`status` reports the platform, the permission state, the surfaces this adapter can read, and the [state root](/desktop/configuration#state-root):

```json
{
  "version": "2.6",
  "ok": true,
  "command": "status",
  "data": {
    "permissions": {
      "accessibility": { "state": "granted" },
      "automation": { "state": "not_required" },
      "screen_recording": { "state": "not_required" }
    },
    "platform": "windows",
    "ref_count": null,
    "session_id": null,
    "snapshot_id": null,
    "state_root": "C:\\Users\\you\\.agent-desktop",
    "supported_surfaces": ["window", "focused", "sheet", "menu", "start-menu", "taskbar", "system-tray", "system-tray-overflow", "action-center"],
    "tracing": false,
    "version": "1.2.0"
  }
}
```

## Grant permissions

Windows needs no accessibility grant for apps at your terminal's integrity level. An app running as administrator can be read but not driven from a lower-integrity terminal; run agent-desktop elevated to the same level. See [Windows](/desktop/platforms/windows).
