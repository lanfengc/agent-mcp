## agent-desktop

- Upstream: https://github.com/vercel-labs/agent-desktop
- Snapshot: `2f6507051f6790e2645ca1afd5bac5ad187354d7` (`main`, imported 2026-11-14)
- License: Apache License 2.0, see `agent-desktop/LICENSE`
- Copyright: Vercel, Inc. and agent-desktop contributors

Local modifications:

- Open existing Windows interaction-lock directories with validation access. Only fresh directories request permission to author a DACL. Keep canonical path, owner, ACL and exclusive file checks.
- Made the desktop project Windows-only. Removed the `crates/macos` and `crates/linux` platform crates and their workspace entries, the macOS VM sandbox provider under `providers/macos`, the `agent-desktop-macos` and `agent-desktop-linux` skills, the macOS, Linux and native install test harnesses under `tests/`, the macOS and Linux documentation pages under `agent-desktop/apps/docs/`, the macOS/Linux CI and release lanes, and the Unix-only FFI leak probe `agent-desktop/tests/ffi-python/leak_probe.py`. The Unix interaction-lease descriptor path was removed from `agent-desktop/crates/ffi` and `agent-desktop/crates/core`; `agent-desktop-windows` is the only platform crate. User-facing prose, skills, help text and comments now describe Windows only; the remaining documentation pages under `agent-desktop/apps/docs/` were rewritten around Windows examples, and the architecture, ref-resolution and sandbox diagrams no longer show other platforms. `agent-desktop/scripts/update-ffi-header.sh` and `agent-desktop/crates/ffi/tests/run_cdylib_panic_probe.sh` resolve their root from the script location rather than `git rev-parse --show-toplevel`, which points at the outer repository here, and the committed C header was regenerated with cbindgen 0.29.4. CI now verifies the release binary version against the workspace after the Windows-only rewrite.
- Added background window clicks: `mouse-click --background --window-id --capture-id`, implemented with `PostMessageW` in `agent-desktop/crates/windows/src/input/mouse/mouse_background.rs` and dispatched through `agent-desktop/crates/core/src/commands/mouse_click_background.rs`.
- Added capture metadata: `capture_id`, `window_id`, `window_bounds`, `capture_bounds` and `capture_time_ms` on window screenshots, bound by `agent-desktop/crates/core/src/system/capture_token.rs`. On Windows, `capture_bounds` is the `DWMWA_EXTENDED_FRAME_BOUNDS` rectangle when the image has that size, and the window bounds otherwise. `PlatformAdapter` gained `capture_bounds` and `ocr_image` with defaults in `agent-desktop/crates/core/src/adapter/system.rs`. Three upstream doc comments in that file and one in `agent-desktop/crates/windows/src/system/adapter.rs` were shortened to keep both files under the 400-line limit.
- Added execution policy: `AGENT_DESKTOP_READ_ONLY`, `AGENT_DESKTOP_ALLOWED_COMMANDS`, `AGENT_DESKTOP_AUDIT_LOG` and `AGENT_DESKTOP_MAX_CAPTURE_AGE_MS`, in `agent-desktop/src/command_policy/safety.rs` and `agent-desktop/src/dispatch/keyboard_mouse.rs`. Read-only mode refuses every command that changes state and keeps the observation commands, including the three that only write a file the caller names (`screenshot PATH`, `clipboard-get --out`, `trace export`). `agent-desktop/src/main.rs` checks the policy before the session placement below, so a relaunched command cannot bypass it.
- Added Windows OCR fallback: `screenshot --ocr`, `--ocr-language` and `--ocr-query`, using `Windows.Media.Ocr` in `agent-desktop/crates/windows/src/system/ocr.rs`, with shared result types in `agent-desktop/crates/core/src/system/ocr_*.rs` and query matching in `agent-desktop/crates/core/src/commands/screenshot.rs`. `agent-desktop/crates/windows/Cargo.toml` adds the `windows-future` crate and the `Foundation_Collections`, `Globalization`, `Graphics_Imaging`, `Media_Ocr`, `Storage_Streams` and `Win32_System_WinRT` features of the `windows` crate for it.
- Added minimized-window capture: `screenshot --window-id` restores a minimized window for `PrintWindow` and minimizes it again, in `agent-desktop/crates/windows/src/system/capture/capture_window.rs`; window geometry uses the placement's normal rectangle in `window_enum.rs`, and `capture_backend.rs` skips Windows Graphics Capture for a minimized window. Two upstream tests that expected a minimized window to be refused now expect the capture: `minimized_windows_are_rejected_before_bitmap_alloc` in `capture_window_tests.rs` and `minimized_window_capture_is_not_delivered_through_the_entry_point` in `screenshot_tests.rs`, both renamed.
- Extended background clicks with `--restore-minimized`, `--cursor-fallback` and `--semantic`, in `agent-desktop/crates/windows/src/input/mouse/mouse_background.rs` and `mouse_background_semantic.rs`, with options in `agent-desktop/crates/core/src/input/background_click_options.rs`. `--semantic` accepts only the left button.
- Added session placement recovery: a command started outside every active WTS session is relaunched on the `Default` desktop of the first active one through `WTSQueryUserToken` and `CreateProcessAsUserW` when the caller holds `SeTcbPrivilege`. A process inside any active session acts on its own desktop. A command is refused when the secure desktop owns input or when no session is active; a session that only shows its lock screen keeps `Default` as its input desktop and is not detected. See `agent-desktop/src/dispatch/desktop_session.rs` and `agent-desktop/crates/windows/src/system/session_probe.rs` / `session_relaunch.rs`. `agent-desktop/crates/windows/Cargo.toml` adds the `Win32_System_Console`, `Win32_System_Environment`, `Win32_System_RemoteDesktop` and `Win32_System_StationsAndDesktops` features of `windows-sys` for it.
- Moved the tracing setup out of `agent-desktop/src/main.rs` into `agent-desktop/src/diagnostic/logging.rs`, which keeps `main.rs` under the 400-line limit.
- Fixed the architecture gate's self-test on Windows: `agent-desktop/scripts/check_architecture.py` now plants its absolute `#[path]` fixture with forward slashes. With backslashes the planted violation never fired on Windows, and a temp path containing `\x` stopped the script with a `ValueError`.
- Updated to upstream 1.3.0: the version in `agent-desktop/Cargo.toml`, `agent-desktop/Cargo.lock` and `agent-desktop/npm/package.json`, and the release entry in `agent-desktop/CHANGELOG.md`. The other commits after the previous snapshot touch only the removed macOS and Linux trees (`crates/linux`, `providers/macos` and the macOS sandbox page): the `rustix` 1.1.6 security bump and the sandbox launcher session fix are not present.
- Updated the matching skills under `agent-desktop/skills/` and the documentation under `agent-desktop/docs/` and `agent-desktop/apps/docs/`. New CLI flags are exposed to MCP automatically from the clap command tree.

## agent-browser

- Upstream: https://github.com/vercel-labs/agent-browser
- Snapshot: `4720bc3dd73f2c8f7c84f415adfa560330b924c4` (`main`, imported 2026-11-14)
- License: Apache License 2.0, see `agent-browser/LICENSE`
- Copyright: Vercel, Inc. and agent-browser contributors

Local modifications:

- Added `AGENT_BROWSER_EPHEMERAL_PROFILE=1` for dedicated local Chromium runs that require an empty profile and refuse profile reuse, state replay and external attachment. Owned browser shutdown bounds the graceful CDP close before existing process cleanup.
- Local Chrome launches without a profile now reuse a persistent per-session profile under the agent-browser state directory, so cookies, storage, and cache survive browser and daemon restarts. Explicit profiles, a `--user-data-dir` or `--profile-directory` switch passed through `--args`, state replay, CA certificates, allowed-domains containment, CDP attach, auto-connect, and non-Chrome engines keep their existing behavior. See `agent-browser/cli/src/native/state.rs` and `agent-browser/cli/src/native/actions.rs`. The same change updates the `open` tool description in `agent-browser/cli/src/mcp.rs` and its generated copy `agent-browser/packages/@agent-browser/sandbox/mcp-tools.json`, the `LaunchOptions.profile` doc comment in `agent-browser/cli/src/native/cdp/chrome.rs`, the help text in `agent-browser/cli/src/output.rs`, and the docs under `agent-browser/docs/` and `agent-browser/skill-data/`. Four original docs lines were rewritten for it, and each is registered in `agent-browser/docs/tests/fixtures/docs-edits.json` so the docs regression suite accepts the new text.
- Made the browser project Windows-only. Removed the six darwin and linux npm platform packages, the Safari/iOS/Appium WebDriver backend under `agent-browser/cli/src/native/webdriver/`, the `--device` and `AGENT_BROWSER_IOS_DEVICE` surfaces, `--no-xvfb` and `AGENT_BROWSER_NO_XVFB`, the Linux NSS/certutil and Xvfb paths, Unix domain sockets and permission checks, the `libc` and `cfg(unix)` dependencies, `agent-browser/scripts/build-all-platforms.sh`, the Docker build files, and the docs pages `ios.mdx`, `eve.mdx` and `next.mdx`. `package.json`, `scripts/postinstall.js`, `scripts/copy-native.js`, `scripts/native.js`, `scripts/stage-native-packages.js`, `scripts/link-native.js` and `bin/agent-browser.js` now resolve only the Windows x64 executable; `build:linux`, `build:macos`, `build:all-platforms` and `build:docker` became `build:windows`. Chrome discovery, install, upgrade and doctor are Windows-only, `agent-browser.schema.json` and `agent-browser/docs/public/schema.json` no longer describe Linux, iOS or Safari behavior, and the MCP catalog was regenerated without the iOS device tool. Docs, skills, `docs/tests/fixtures/docs-edits.json`, `docs/tests/helpers.mjs` and the navigation lists now describe Windows x64 only. The Rust, packaging and release jobs in CI run on `windows-latest`; JavaScript-only docs, dashboard and publish jobs stay on `ubuntu-latest` because they produce no platform artifacts. The `@agent-browser/sandbox` and `@agent-browser/eve` packages, their `examples/` apps and documentation, the PnPm release-age exemptions for them, and their version-sync, CI and npm publish wiring were removed, along with the MCP tool catalog snapshot test that wrote into the sandbox package. Four Unix-only integration test files (`batch_cli.rs`, `session_files_cli.rs`, `session_settings_cli.rs`, `skills_cli.rs`) were deleted; the remaining Unix-only test cases were removed, and the MCP batch, install and session-settings tests were made Windows-robust by preserving `SystemRoot`/`WINDIR` in a cleared environment, bounding the daemon idle timeout, accepting the Winsock 10061 refusal code, and using absolute policy paths. The Node launcher tests now build their fake executables from the running `node.exe` plus a CommonJS stub that reads a marker file, because the previous POSIX shell scripts could not run as `.exe` files on Windows, and the four POSIX-only pnpm bin-shim tests were removed.
- Updated to upstream 0.43.0. The Windows-relevant changes are the device-scale recording fix (#2572), failing commands on a detached CDP session instead of waiting for the timeout (#2576), snapshot hints for controls whose name is empty or shared (#2578), the Modern Web Guidance skill (#2577), and the renamed `vercel` skill with feature flag overrides (#2441). The version is bumped in `agent-browser/package.json`, `agent-browser/cli/Cargo.toml`, `agent-browser/cli/Cargo.lock`, `agent-browser/packages/@agent-browser/cli-win32-x64-msvc/package.json` and `agent-browser/packages/dashboard/package.json`, with the matching `CHANGELOG.md`, docs pages, skill data and eval cases. The test module in `agent-browser/cli/src/native/actions.rs` imports `tokio::net::TcpListener` directly, because the import that upstream kept for the removed WebDriver tests no longer exists here. Not imported: the `vercel-sandbox` skill, because it documents the removed `@agent-browser/sandbox` package; the tests added to `agent-browser/cli/tests/skills_cli.rs`, because that file is removed here; and the darwin, linux, eve and sandbox packages that this repository does not carry.
